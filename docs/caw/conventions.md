## Archetype

- Archetype ID: `nextjs-feature`
- Summary: Single-page Next.js 16 (App Router) client app with API route proxies. No separate backend service — all server-side logic lives in `src/app/api/` route handlers.
- Primary surfaces:
  - Frontend shell: `src/app/page.tsx` (client component, orchestrates all state)
  - Backend style: Next.js API routes as server-side proxies (hide keys, avoid CORS, add caching)
  - Integration boundary: Supabase (realtime + storage), Open-Meteo, RainViewer, WorldTides, OpenWeatherMap, open-elevation

## Stack

- Frontend: Next.js 16 + React 19 + Tailwind CSS v4 (config-less, @tailwindcss/postcss)
- Map: MapLibre GL + react-map-gl, Carto Positron style (no Mapbox token)
- UI primitives: shadcn/ui (new-york style) + lucide-react icons + sonner toasts
- Database / realtime: Supabase (postgres_changes realtime, RLS-open sos_reports table, sos-images storage bucket)
- Geospatial: @turf/turf for isoband grid computation, haversine in JS for distance filtering
- Caching: lru-cache for elevation tile responses
- Linter/formatter: Biome (not Prettier/ESLint for formatting)
- Package manager: pnpm

## Code Organization Patterns

- `page.tsx` owns all top-level state; child components receive props — no global state library (no Zustand/Redux).
- `Promise.allSettled` fan-fetch pattern for parallel upstream calls; each leg degrades independently on failure.
- API routes return empty safe payloads (empty GeoJSON `FeatureCollection`, transparent 1x1 PNG) on upstream failure — never propagate upstream errors as HTTP errors.
- `/api/risk` calls `/api/isobands` over HTTP using base URL from `x-forwarded-proto` / `host` headers.
- Supabase `created_at` / `updated_at` are epoch milliseconds stored as BIGINT (not timestamps).
- DB columns are snake_case; API layer transforms to camelCase `SosReport` shape on the way out.
- `SosReport` canonical type is defined in `src/components/MapView.tsx` and imported elsewhere.
- Path alias: `@/*` → `src/*`.
- Offline queue: `src/lib/sos-queue.ts` uses `localStorage` + `online` event for retry.

## Forbidden Patterns

- Using Prisma, Drizzle, or any ORM — database access is via `@supabase/supabase-js` only.
- Using axios or node-fetch directly in components — use Next.js API routes as proxies.
- Fetching third-party APIs (RainViewer, Open-Meteo, WorldTides, etc.) from the browser — all must go through API route proxies.
- Hardcoding API keys in client-side code — keys are server-only env vars.
- Using `SUPABASE_SERVICE_ROLE_KEY` without checking it looks valid — fall back to anon key.
- Changing risk threshold behavior anywhere outside `src/lib/risk.ts`.
- Using PostGIS — schema has no PostGIS; distance filtering is Haversine JS inside the GET route.
- Running `pnpm check` with `--no-write` in dev — use `pnpm check` (writes) locally, `pnpm check:ci` in CI.
- Relying on `.cursor/rules/*.mdc` or README project structure — those describe a different stack (NestJS/Prisma/AWS/Stripe); trust `src/` tree.

## Stack Overrides

- No monorepo — single `package.json` at root, no `apps/` or `packages/` workspaces despite `pnpm-workspace.yaml` being present.
- Biome is the primary formatter AND linter. ESLint (`pnpm lint`) is also wired via `eslint-config-next` for Next.js-specific rules. Run both before committing.
- UI strings are in Vietnamese — do not translate or replace with English in components.
- Commit messages follow Conventional Commits: `feat:`, `fix:`, `chore:`, `refactor:`, `docs:`.
