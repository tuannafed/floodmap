# Project Rules — SOS / FloodMap

> Generated by /caw-setup. These are project-specific rules that override
> generic defaults in `common/` and `typescript/`. Edit freely; re-run
> `/caw-setup --refresh` to regenerate from stack detection.

## Stack lock-ins

> Hard constraints derived from CLAUDE.md + package.json. Agents must respect these.

- Map: **MapLibre GL via `react-map-gl`** (free Carto Positron style,
  `MAP_STYLE_URL` in `src/constants/index.ts`). No Mapbox token, no Mapbox GL JS —
  the README's Mapbox-token instructions are stale, ignore them.
- Database client: **plain `@supabase/supabase-js`**, no ORM (no Prisma, no
  Drizzle). Schema lives in `supabase/migrations/*.sql`, applied manually via
  the Supabase SQL editor — there is no migration CLI wired up, so never
  propose `supabase db push`/`migrate` commands that assume one.
- Lint/format: **Biome only**. `eslint` / `eslint-config-next` are present in
  `devDependencies` but unused (no config file, and `next lint` is removed in
  Next 16) — never propose `pnpm lint` or an ESLint fix.
- Package manager: **pnpm** (`pnpm-lock.yaml`, `pnpm-workspace.yaml` present).
  No `.npmrc` and no `packageManager` field currently pinned in `package.json`.
- Testing: **none configured**. No Jest/Vitest/Playwright, no test files.
  Verification is `npx tsc --noEmit` + `pnpm check:ci` + manual browser check —
  do not invent or suggest `pnpm test:*` scripts (several exist in
  `package.json` but point at a `scripts/` directory that doesn't exist and
  fail immediately).

## Forbidden patterns

> Things this project has explicitly rejected. Cite the reason if known.

- No direct client-side fetches to third-party upstreams (Open-Meteo,
  WorldTides, RainViewer, OpenWeatherMap, open-elevation.com) — always go
  through this app's own `/api/*` proxy route, to hide keys, avoid CORS, and
  keep caching centralized.
- No throwing from an API route on upstream failure — every route degrades to
  a safe empty shape (`{}`/empty `FeatureCollection`/transparent 1×1 PNG) so
  the map never hard-crashes on a third-party outage. Preserve this pattern
  when touching `nowcast`, `tides`, `risk`, `isobands`, `radar-tiles`,
  `owm-tiles`.
- No assuming `SUPABASE_SERVICE_ROLE_KEY` is set in `createServerClient()` —
  it falls back to the anon key on purpose, and this only works because RLS
  policies allow public read/insert/update on `sos_reports`.
- No treating `sos_reports.created_at` / `updated_at` as SQL timestamps — they
  are epoch-milliseconds stored as `BIGINT`.

## Conventions overrides

> Where this project deviates from caw defaults in `common/coding-standards.md`
> and `typescript/coding-style.md`.

- Quote style / semicolons: **do not blanket-reformat.** The existing source
  mostly uses single quotes and omits semicolons, which does not match the
  Biome config (double quotes, semicolons). A full `pnpm check` write would
  reformat the whole tree and bury unrelated diffs — format only the files
  you actually touch (`npx biome check --write <paths>`), and match
  surrounding style in files you edit rather than the Biome default.
- DB naming: DB columns are snake_case (`people_count`, `has_vulnerable`,
  `image_url`); the API layer converts to camelCase on the way out. The
  canonical `SosReport` interface lives in `src/components/MapView.tsx` — import
  it from there, don't redeclare a parallel shape.

## Domain rules

> Business / domain constraints that agents need to respect when changing code.

- SOS reports update live via `useRealtimeSOS` (`src/hooks/useRealtimeSOS.ts`)
  subscribing to Supabase `postgres_changes` on `sos_reports`; the 5-minute
  poll in `page.tsx` is the fallback/initial-load path, not the primary update
  mechanism — don't remove the realtime subscription in favor of polling.
- Offline SOS submissions are queued client-side in `localStorage`
  (`src/lib/sos-queue.ts`) and auto-retried on the browser `online` event —
  preserve this when touching the SOS submit flow.
- UI strings are in Vietnamese — keep new user-facing copy in Vietnamese unless
  told otherwise.
